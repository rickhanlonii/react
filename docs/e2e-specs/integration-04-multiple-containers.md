# Multiple Containers with identifierPrefix

## Category
integration

## Description
Validates that multiple independent React roots can coexist on the same HTML document using the `identifierPrefix` option. Each root is server-rendered with `renderToPipeableStream` using a distinct prefix, and each root is hydrated independently on the client with `hydrateRoot` using the same prefix. The `identifierPrefix` ensures that internal IDs generated by `useId`, Suspense boundary markers, and other React-internal identifiers do not collide between roots. This is critical for microfrontend architectures and widget embedding scenarios.

## App Setup
```jsx
// Server: server.js
import { renderToPipeableStream } from 'react-dom/server';
import { WidgetA, WidgetB } from './Widgets';

function handleRequest(req, res) {
  res.statusCode = 200;
  res.setHeader('Content-Type', 'text/html');

  // Write the document shell manually
  res.write('<!DOCTYPE html><html><head><title>Multi Root</title></head><body>');

  let completedRoots = 0;
  const totalRoots = 2;

  function checkAllDone() {
    completedRoots++;
    if (completedRoots === totalRoots) {
      res.write('<script src="/client.js" async=""></script>');
      res.write('</body></html>');
      res.end();
    }
  }

  // Render Widget A with prefix "A_"
  res.write('<div id="container-A">');
  const { pipe: pipeA } = renderToPipeableStream(<WidgetA />, {
    identifierPrefix: 'A_',
    onAllReady() {
      pipeA(res);
      res.write('</div>');
      checkAllDone();
    },
  });

  // Render Widget B with prefix "B_"
  res.write('<div id="container-B">');
  const { pipe: pipeB } = renderToPipeableStream(<WidgetB />, {
    identifierPrefix: 'B_',
    onAllReady() {
      pipeB(res);
      res.write('</div>');
      checkAllDone();
    },
  });
}

// Client: client.js
import { hydrateRoot } from 'react-dom/client';
import { WidgetA, WidgetB } from './Widgets';

hydrateRoot(
  document.getElementById('container-A'),
  <WidgetA />,
  { identifierPrefix: 'A_' }
);

hydrateRoot(
  document.getElementById('container-B'),
  <WidgetB />,
  { identifierPrefix: 'B_' }
);

// Shared: Widgets.js
import { useState, useId, Suspense } from 'react';

function LabeledInput({ label }) {
  const id = useId();
  const [value, setValue] = useState('');
  return (
    <div>
      <label htmlFor={id}>{label}</label>
      <input
        id={id}
        value={value}
        onChange={e => setValue(e.target.value)}
      />
      {value && <p className="echo">You typed: {value}</p>}
    </div>
  );
}

function AsyncContent({ text }) {
  // Simulates async data
  const resource = createResource(text, 200);
  return <p>{resource.read()}</p>;
}

export function WidgetA() {
  const [count, setCount] = useState(0);
  return (
    <div className="widget-a">
      <h2>Widget A</h2>
      <LabeledInput label="Name (A):" />
      <LabeledInput label="Email (A):" />
      <button id="btn-a" onClick={() => setCount(c => c + 1)}>
        Clicked A: {count}
      </button>
      <Suspense fallback={<span>Loading A data...</span>}>
        <AsyncContent text="Widget A async content" />
      </Suspense>
    </div>
  );
}

export function WidgetB() {
  const [count, setCount] = useState(0);
  return (
    <div className="widget-b">
      <h2>Widget B</h2>
      <LabeledInput label="Name (B):" />
      <LabeledInput label="Email (B):" />
      <button id="btn-b" onClick={() => setCount(c => c + 1)}>
        Clicked B: {count}
      </button>
      <Suspense fallback={<span>Loading B data...</span>}>
        <AsyncContent text="Widget B async content" />
      </Suspense>
    </div>
  );
}
```

## Load Sequence
1. Client sends HTTP GET request to the server.
2. Server writes the document shell (`<!DOCTYPE html><html>...`) and two container `<div>` elements.
3. Server calls `renderToPipeableStream(<WidgetA />, { identifierPrefix: 'A_' })` and `renderToPipeableStream(<WidgetB />, { identifierPrefix: 'B_' })` concurrently.
4. Each render generates HTML where all internal IDs (`useId` values, Suspense boundary comment markers) use the respective prefix. For example, Widget A's `useId` returns `:A_r0:` and Widget B's returns `:B_r0:`.
5. As each widget's `onAllReady` fires, the HTML is piped into the respective container div.
6. After both renders complete, the server writes the client script tag and closes the document.
7. The browser receives the full HTML with both widgets rendered.
8. The client JavaScript loads and calls `hydrateRoot` separately for each container, passing the matching `identifierPrefix`.
9. React hydrates each root independently. The prefix ensures that React matches the correct server-generated IDs during hydration.

## Actions
1. Navigate to the page URL and wait for the full document to load.
2. Inspect the generated IDs in the DOM: verify Widget A's `<label>` and `<input>` use IDs starting with `:A_` and Widget B's use IDs starting with `:B_`.
3. Wait for hydration of both roots to complete.
4. Click the "Clicked A: 0" button in Widget A.
5. Click the "Clicked B: 0" button in Widget B.
6. Type "Alice" into Widget A's "Name (A)" input.
7. Type "Bob" into Widget B's "Name (B)" input.
8. Verify each widget's state is independent.

## Assertions
1. The DOM contains two container divs: `#container-A` and `#container-B`.
2. Widget A's `<input>` elements have `id` attributes starting with `:A_` (e.g., `:A_r0:`).
3. Widget B's `<input>` elements have `id` attributes starting with `:B_` (e.g., `:B_r0:`).
4. Widget A's `<label>` elements have `htmlFor` attributes that match their corresponding `<input>` `id` attributes.
5. Widget B's `<label>` elements have `htmlFor` attributes that match their corresponding `<input>` `id` attributes.
6. No ID collisions exist between Widget A and Widget B in the entire document.
7. After hydration: no hydration mismatch errors for either root.
8. Clicking Widget A's button updates only Widget A's count to "Clicked A: 1". Widget B's count remains "Clicked B: 0".
9. Clicking Widget B's button updates only Widget B's count to "Clicked B: 1". Widget A's count remains "Clicked A: 1".
10. Typing into Widget A's input shows "You typed: Alice" only in Widget A. Widget B is unaffected.
11. Typing into Widget B's input shows "You typed: Bob" only in Widget B. Widget A is unaffected.
12. Each Suspense boundary resolves independently within its own root with the correct content.
